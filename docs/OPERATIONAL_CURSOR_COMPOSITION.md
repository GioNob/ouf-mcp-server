# Bounded composition of independent owner snapshots

This implementation follows the [platform resilience policy](https://github.com/GioNob/ouf-deploy/blob/main/docs/OUF_RESILIENCE_POLICY.md), MCP PET 1.4 and Gateway PET 1.5. It is a private read primitive awaiting public adapter and Gateway delegation qualification. Existing public query schemas and runtime deployment are unchanged.

`CursorComposer` builds a vector of Ingestion and Gateway snapshots through the existing governed caller. It stores only identity-bound owner cursor positions, canonical visible payload digests, separately reported owner digests, immutable filters and MCP's own public self state in the existing PostgreSQL metadata store. It does not cache producer incident payloads or delegation tokens, aggregate distinct owner incidents into a speculative root cause, or claim a transaction spanning independent services.

Each invocation has a 2.5-second overall deadline and at most three governed owner calls. Those are an attempt budget, not an outage retry policy. Existing persistent caller admission, object/byte budgets and retry guards remain in force. A readback uses the saved Ingestion source scope for authorization while sending a cursor-only body. Gateway always retains its separately authorized restricted platform scope.

Initial capture requests priority ordered pages of 100 objects from each owner. Continuations re-fetch both current owner pages, including completed owners, with current authorization. Canonical payload and owner digests, snapshot identity and cursor must agree with the saved frame. A changed policy, identity, redaction, payload, self state or inconsistent owner ordering invalidates the page; a missing, expired or partial owner supplies no durable progression. This strict primitive does not replace the existing explicitly partial bounded legacy projection.

The merge compares unresolved state, owner-declared severity, action requirement, last observation, owner and incident ID before applying the aggregate limit. It may refill one exhausted owner page. If another head is unknown when the three-call bound is reached, it ends the page early and reports `coverage.scanPending`; it does not guess that unknown owner's priority. Independent snapshots, their owner history gaps and current authorization are not an atomic platform-wide observation.

An unchanged replay receives the same continuation through the metadata store's append CAS. Result and next-frame mismatches are fenced. Failures do not commit the attempted continuation. Metadata quotas, 30-minute expiry and a maximum 200 continuation pages bound abandoned state; no infinite internal paging loop exists. Delivery failures cannot turn a saved page digest into a consultation receipt: `consultationRecorded` remains false on every response.

Qualification covers priority across pages, restart and replay, concurrent continuation, owner failure, changed visibility and payload with a forged unchanged reported digest, policy and principal binding, source-scope retention, bounded refill, unknown filters, completed-owner reauthorization and changed MCP self state. Native qualification status is recorded after CI completes.

Remaining work: freshly authorized root handler; governed public cursor schema/profile and Gateway materialization; transport of a validated delegated context specifically to the aggregate MCP owner (never arbitrary downstream forwarding); real service budget composition; publication-boundary catch-up bookmarks; explicit client delivery receipt and monotone operator checkpoint; retention cleanup and HA qualification. No VPS operation, email, shared-lock wait, budget reset, R9/R10 replay, production migration or release acceptance is performed by this implementation.
