# Delegated context for governed operational aggregation

The aggregate owner now consumes the Gateway-verified opaque context required by nested governed calls. The MCP HTTP client selects only the six fixed reviewed capability paths materialized by [Gateway operational execute](https://github.com/GioNob/ouf-api-gateway/blob/main/docs/OPERATIONAL_EXECUTE_MEDIATION.md); other capability IDs cannot create arbitrary URLs. Public status and Authorization permission paths retain their existing mediation.

On summary/incidents only, a proof-bearing request must have the trusted Gateway marker, `mcp-operational-aggregate-v1` verified-context marker, exact aggregate capability, HUMAN subject and configured MCP workload. The expected workload comes from `MCP_OIDC_CLIENT_ID`; absent configuration denies proof-bearing requests. Proof syntax/size are bounded. MCP trusts the isolated Gateway boundary for initial verification; every nested Gateway hop independently re-verifies its signature, expiry, signed identity/roles/coarse scope and current workload bearer. The opaque proof is request-only, never a stored grant, serialized payload, log field or response.

Owner-local root Authorization is evaluated first, as is every producer collection/item authorization. A granted summary does not grant incident or restricted platform visibility. The original signed HUMAN context is preserved while the transport is an independently verified MCP workload. SDK decisions, source scope, persistent admission and finite budget guards remain active. The owner does not disable `RequireDelegation`, mint a HUMAN session or issue new signatures.

Tests drive the actual orchestration Service with `RequireDelegation=true` through the aggregate owner, confirm separated proof transport and two governed producer calls, and deny missing/malformed markers, changed workload/actor/capability and absent configuration before owner reads. HTTP adapter tests cover all six fixed paths and deny arbitrary capability URL selection. Gateway real APISIX/OIDC qualification remains a separate required dependency.

Legacy channel-neutral requests without this proof retain their explicitly partial bounded projection when the real governed caller requires delegation. The private cursor composer remains unwired to the public query schema pending root handler, budget composition and publication-boundary/operator delivery receipt qualification. No deployment, target migration/restart, local Gateway SDK grants, email, R9/R10 replay or release acceptance is inferred from these tests. Follow the [platform resilience policy](https://github.com/GioNob/ouf-deploy/blob/main/docs/OUF_RESILIENCE_POLICY.md) and PETs.
